Agent catalogue · 31

Every agent, its code and its SHA-256

Thirty-one agents that run on the reference hearth, hestia.modelmarket.dev, sold by modelmarket (payouts to the treasury). The hearth signs every answer with Ed25519 over the result, the capability and the SHA-256 of the input. Most agents are pure functions of their input: no clock, no network, no randomness, so the same request always gets the same answer and the same signature, and anyone can re-run it to check. The ones that read public sources (a chain, a registry, DNS, a site) say so below: their hosts are public on the hearth's roster, they reach only those and any host you name in the call, and where the state they read moves they pin a block or say what they read. They all run in the hearth's WebAssembly sandbox.

Base RPC. Agents that read Base ask the hearth's own pool first, base-rpc.hestia.modelmarket.dev: the hearth answers that name itself, from a cache for reads pinned to a block and from free public Base RPCs in turn, so one busy agent does not use up a public RPC's per-address limit for every other. On a hearth without the pool they read the public RPC named in their entry.

rules.decide@v1

Evaluates a versioned rule set against facts and returns the decision, the rule that fired, and a trace of why each earlier rule did not. Numbers compare as decimals, a missing fact fails its condition instead of raising, and the answer names the SHA-256 of the policy and of the facts — so a receipt says exactly which policy version decided. Use it for limits, refunds, access decisions you may have to justify.

 "facts": {"days": 31}}

x402-check

x402.authorization.check@v1
$0.003Pythonchecking…

Checks a signed USDC transferWithAuthorization (the x402 exact scheme on EVM) before anyone submits it: recomputes the EIP-712 digest, recovers the signer, and runs USDC's own checks (v 27/28, low s, signer, validity window) and the seller's (pay_to, amount, asset, network, bound nonce). Knows the EIP-712 domains of USDC on Ethereum, Base, Base Sepolia, Arbitrum, OP, Polygon and Avalanche, read from the contracts — Base Sepolia's name is USDC, the mainnets' USD Coin, the commonest reason a payment reverts.

{"x_payment": "<the X-PAYMENT header>", "requirements": {"network": "base", "maxAmountRequired": "22000",
 "payTo": "0x…", "asset": "0x8335…2913"}, "now": 1791119999}

When the signature does not recover to from, the answer tries the usual slips — the other USDC name, version 1, the other authorization type, Base for Base Sepolia — and names the domain it was really signed for (diagnosis).

Offline: whether the nonce is unused and the balance covers it are listed under not_checked.
