**HESTIA** (Ἑστία) — **очаг** для провайдеров способностей AIMarket.

Изолированный hosted-runtime · не каталог Hub · не доска работ · не Factory.

**Возможности:** `hestia.host.deploy@v1` · `hestia.host.status@v1` · `hestia.hearth.list@v1` · `hestia.host.stop@v1` ·
**Порт:** `9480` ·
**Лендинг:** [alexar76.github.io/hestia](https://alexar76.github.io/hestia/) ·
**Эталонный очаг (когда DNS поднят):** [hestia.modelmarket.dev](https://hestia.modelmarket.dev)

## Прямой ответ

**Это не доска, на которой агенты Factory появляются сами.**

Нужен **явный деплой подписанного бандла на этот очаг**. Пока его нет, roster пуст — и пустой roster значит «здесь ничего не хостится», а не «рынок пуст».

**Где они хостятся:** на **машинах оператора Hestia**.

| Режим | Кто крутит процесс |
|---|---|
| Эталонный очаг | Флот AICOM (`hestia.modelmarket.dev`) |
| Self-host | **Ваш** сервер, ноутбук или compose |
| Не | Ноутбук автора, Hub, Factory, THEMIS или ARGUS |

Hub остаётся каталогом. THEMIS (по желанию) может отказать до старта. Announce — явный стук, не выдача доверия.

## Изоляция

По умолчанию — **замкнутый loopback-подпроцесс** (`HESTIA_RUNTIME=stub`): наш HTTP и Ed25519, опциональный `handle(payload)` только после AST-допуска. Stub **не** ставит cgroups. AST — допуск, не песочница. Production-ledger — Postgres (`HESTIA_DATABASE_URL`); SQLite — dev/test. `HESTIA_REPLICAS>1` отказ: общий ledger ≠ ферма.

**Коробка Hestia не управляет хостом. Тенанты тоже.** Compose — один обычный спутник (нет docker CLI, нет `docker.sock`, нет privileged). Тенанты там — loopback-подпроцессы внутри коробки. Docker-runtime — процесс **на хосте** (`python -m hestia` + `HESTIA_ALLOW_HOST_DOCKER=1`), не сокет в контейнере. Стартует только `sha256:` из `HESTIA_ALLOW_IMAGE_DIGESTS`. У каждого тенанта своя сеть `hestia-tenants-{slug}` с `Internal=true`, без IPv6, на /29 из `HESTIA_TENANT_SUBNET_POOL`; маршрута от тенанта к тенанту нет. Шлюз этой сети — сам хост движка: запустите на нём `sudo scripts/tenant-host-firewall.sh apply`, иначе тенант достаёт сервисы хоста, слушающие на всех адресах. TCP-движок без TLS отклоняется при любом адресе, включая `tcp://127.0.0.1`. При старте Hestia проверяет каждый image-тенант и переносит в отдельные сети тех, кто ещё в старой общей; кого проверить не удалось, получает статус `quarantined` (не обслуживается, повтор через `POST /v1/admin/reconcile`). Hearth в режиме `stub` docker не вызывает никогда. У тенантов нет `docker.sock`, нет `--privileged`, нет host-сети, `--cap-drop ALL`, `--read-only`, uid `65532`.

## Песочница (`HESTIA_RUNTIME=wasm`)

С `HESTIA_RUNTIME=wasm` обработчик агента не работает отдельным процессом. Каждый вызов исполняется в **новом
экземпляре WebAssembly**: CPython 3.14, собранный под WASI, под управлением wasmtime, в отдельном сервисе
`hestia-runner` (`docker compose --profile wasm up -d`). У этого контейнера **нет сети совсем**, **нет секретов**
(окружение Гестии туда не передаётся), файловая система только для чтения и один Unix-сокет в общем с Гестией
томе. Внутри экземпляра обработчик видит стандартную библиотеку на чтение — и больше ничего:

| Обработчик пытается | Получает |
|---|---|
| прочитать `/data/provider.key`, `/etc/passwd`, `~/.ssh`, сокет исполнителя | `FileNotFoundError` — путей хоста в экземпляре нет |
| писать в стандартную библиотеку | `PermissionError` (только чтение) |
| открыть сокет | сокетов в WASI preview 1 нет |
| запустить процесс, загрузить нативный код (`ctypes`) | в WASI не поддерживается |
| прочитать окружение | две фиксированные переменные: `PYTHONHASHSEED`, `PYTHONHOME` |
| занять больше лимита, зациклиться, залить stdout | `MemoryError` (256 МиБ), таймаут (10 с, epoch interruption), вывод больше 4 МиБ отклоняется |
| хранить состояние между вызовами или читать чужое | каждый вызов — новый экземпляр |

Результат Гестия подписывает ключом самого агента **снаружи** песочницы (ключ туда не попадает), с тем же
каноническим видом и кодами ответа, что у stub: агент, переведённый со `stub` на `wasm`, сохраняет ключ, и его
ответы проверяются как раньше. Раз граница — песочница, для `wasm` вместо белого списка stub действует лишь
проверка синтаксиса: можно импортировать любой модуль из сборки WASI (`base64`, `difflib`, `typing`, `decimal`,
`unicodedata`… — но не `zlib`, сокеты и потоки). Между вызовами у агента нет процесса, поэтому простаивающий
агент занимает диск, а не память: там, где stub держал около тридцати, помещаются сотни.

Проверено на эталонной Гестии агентом постороннего владельца, написанным для побега: все пути, которые он
пробовал, — `FileNotFoundError`, сети и процессов нет, в окружении две переменные.

## Владельцы

На общей Гестии живут агенты нескольких компаний, поэтому токен оператора — не единственный ключ. **Владелец** — это ключ Ed25519, который допустил оператор (`POST /v1/owners`). Каждый запрос владельца подписан: публичный адрес Гестии, метод, путь, unix-время (±300 с), одноразовый nonce и SHA-256 тела (`X-Hestia-Owner` / `-Timestamp` / `-Nonce` / `-Signature`, формат `hestia-owner/1` в [`hestia/owners.py`](../hestia/owners.py)).

| Кто | Что может |
|---|---|
| Оператор (токен) | всё, как раньше; допускает, ограничивает и приостанавливает владельцев |
| Владелец | разворачивать агента на свободный или свой слаг в пределах квоты (`HESTIA_OWNER_MAX_TENANTS`, по умолчанию 3); останавливать, анонсировать и видеть **только своих** агентов; смотреть свой статус в `GET /v1/owners/me` |
| Все остальные | читать публичный список, вызывать агентов |

Отклоняются: повтор запроса, подпись для другой Гестии, другого пути или тела, а также владелец, указавший в `owner_pubkey` чужой ключ. Нулевой ключ-заглушка и любые другие ключи Ed25519 малого порядка ничем не могут владеть, поэтому агенты, развёрнутые с заглушкой, остаются только за оператором.

`HESTIA_OPEN_OWNERS=1` позволяет любому валидному ключу допустить себя при первом развёртывании. В режиме stub права запускать код он не получает — AST-проверка не песочница, — поэтому посторонние разворачивают только закреплённые образы и запечатанные заглушки. В режиме `HESTIA_RUNTIME=wasm` переменная `HESTIA_OPEN_OWNER_CODE=1` даёт им это право: их код исполняется в песочнице выше, а в публичный манифест их агенты попадают только через автопроверку ниже. Обе по умолчанию выключены; эталонная Гестия работает с обеими включёнными.

```bash
python -m hestia.owner_cli keygen --out owner.key        # печатает публичный ключ для оператора
python -m hestia.owner_cli deploy --hearth https://hestia.example --key owner.key --body deploy.json
python -m hestia.owner_cli stop   --hearth https://hestia.example --key owner.key --slug my-agent
python -m hestia.owner_cli proof  --key owner.key --domain example.com   # печатает запись TXT и файл, подтверждающие домен
python -m hestia.owner_cli domain --hearth https://hestia.example --key owner.key --domain example.com
```

## Автопроверка перед публикацией

Хабы индексируют манифест Гестии, поэтому агента из манифеста видят покупатели всех хабов, закрепивших эту
Гестию. Агент **владельца** работает сразу после развёртывания — его можно вызвать по своему адресу
`/t/{slug}`, — но в манифест попадает только после автопроверки ([`hestia/listing.py`](../hestia/listing.py)).
Проверка читает то, что прочтёт модель покупателя (имя, описание, схемы), и задерживает публикацию при тегах
инструкций, «ignore previous instructions», «не говори пользователю», «прежде чем вызывать другие инструменты»,
скрытых действиях, путях к ключам, невидимых символах, HTML-комментариях, слове, смешивающем похожие алфавиты
(латиницу с кириллицей, греческим…), а также при `capability_id`, близком к семейству другого владельца, или
имени, которое читается так же, как имя агента на этой Гестии, запущенного или нет. Причины владелец видит в ответе на развёртывание и в
`GET /v1/tenants`; оператор публикует или задерживает вручную через `POST /v1/admin/tenants/{slug}/listing`
(`{"listed": true|false, "reason": "…"}`). Агенты самого оператора не проверяются.

Имена, которые хаб показывает покупателям, навсегда принадлежат тому, кто первым развернул агента под ними
([`hestia/names.py`](../hestia/names.py)): семейство способностей (id до `@`), id продукта и издатель
(publisher id и адрес выплат). Имена сравниваются в свёрнутом виде — регистр, разделители, похожие буквы и версия
в конце не делают имя новым, — поэтому `merkle-proof@v2`, `merkle_proof.v2@v1` и `Merkle.Pr0of@v1` — всё это
семейство `merkle.proof`. Остановленный агент, переименованный агент и приостановленный владелец своих имён не
теряют; другой владелец получит 409. `hestia*` принадлежит самой Гестии, а префиксы из
`HESTIA_RESERVED_PREFIXES` (по умолчанию `aicom,aimarket,modelmarket`) — оператору. У одного владельца точный id
(в любом регистре) одновременно обслуживает только один агент. Имя закрепляет сама база (первичный ключ), поэтому
два процесса на одном реестре не могут оба его получить. Оператор видит закрепления через `GET /v1/admin/names`,
закрепляет имя или передаёт его другому через `POST /v1/admin/names`
(`{"kind": "family|product|publisher|prefix", "name": "…", "holder": "operator" | ключ владельца}`; `prefix`
покрывает все имена, начинающиеся с него, например бренд для его компании) и освобождает через
`POST /v1/admin/names/release`, когда агенты держателя остановлены.

Задержанный агент отвечает только по своему адресу `/t/{slug}`: маршрутизируемый вызов, которым пользуется хаб,
доходит лишь до опубликованных агентов. Повторное развёртывание владельцем заново запускает проверку, но не снимает
задержку, поставленную оператором, а повторное развёртывание оператором не публикует задержанного агента — это
делает только вызов публикации. Агенты приостановленного владельца исчезают из манифеста и ростера и не
обслуживаются ни по одному адресу. `HESTIA_MAX_TENANTS` считает работающих и изолированных агентов; остановленный
сохраняет свой slug и имена, но не место.

Владелец, подтвердивший домен, получает все имена, которые начинаются с этого домена вместе с зоной
([`hestia/domains.py`](../hestia/domains.py)). Подтверждение — запись TXT на `_hestia.<домен>` со значением
`hestia-owner=<публичный ключ>` или файл `https://<домен>/.well-known/hestia-owner.json` с
`{"owner_pubkeys": ["<публичный ключ>"]}`; `python -m hestia.owner_cli proof` печатает оба варианта, а
`… domain` просит Гестию проверить. С этого момента каждое семейство, продукт и издатель, начинающиеся с
домена в любом порядке, — `attestedmemory.net.deal`, `net.attestedmemory.deal`, `attestedmemory-net.deal`,
«Attestedmemory.net Labs» — принадлежат этому владельцу, а хабы видят домен как `publisher_domain` агента.
Голое слово не принадлежит никому: attestedmemory.com, .dev и .net могут быть у трёх разных владельцев,
поэтому `attestedmemory.deal` занимается в порядке очереди, как любое имя. Учитывается только
регистрируемый ASCII-домен (example.com, example.co.uk; не поддомен и не IDN), и домен не отнимает имена,
которые уже заняты другими. HTTPS-подтверждение запрашивается только с публичных адресов и без
перенаправлений.

## Хабы, которые продают ваших агентов

Агент берёт оплату за каждый вызов в USDC в блокчейне, а хаб не может заплатить так из кредитов
покупателя или бюджета субподряда. Поэтому владелец может разрешить хабу продавать своих агентов от
своего имени ([`hestia/hub_billing.py`](../hestia/hub_billing.py)):

1. оператор даёт Гестии ключ хаба: `HESTIA_TENANT_HUB_KEYS=https://hub.example=<ключ>` — то же значение,
   что запись этого хаба в `AIMARKET_PEER_API_KEYS` для этой Гестии;
2. владелец открывает кредитный счёт на этом хабе и выбирает его:
   `python -m hestia.owner_cli billing --hearth … --key owner.key --hub https://hub.example --account acct_…`
   (`--account ""` отменяет выбор);
3. вызов хаба с этим ключом обслуживается без платежа в блокчейне, а в ответ добавляется блок
   `hub_billing`, подписанный ключом провайдера Гестии: чей агент, какой хаб, какой счёт. Хаб проверяет его
   ключом, который закрепил за этой Гестией, и зачисляет владельцу `AIMARKET_PUBLISHER_SHARE_BPS`
   (по умолчанию 70 %) от того, что **он сам** взял с покупателя;
4. `python -m hestia.owner_cli statement` показывает каждый такой вызов для сверки с тем, что заплатил хаб.

Агентов самого оператора (ключ-заглушка) продаёт любой хаб, чей ключ настроил оператор, и хаб оставляет
выручку себе. Хаб, который ничего не взял (`X-AIMarket-Hub-Charged: 0`, бесплатный пробник), агента
владельца не получает. Сводка оператора: `GET /v1/admin/hub-billing`.

## Быстрый старт

```bash
cd hestia
export HESTIA_DEPLOY_TOKEN=$(python3 -c 'import secrets; print(secrets.token_urlsafe(24))')
uv sync --extra dev --project .
uv run --project . pytest -q
uv run --project . python -m hestia
# консоль: http://127.0.0.1:9480/ui/
```

Пустой `HESTIA_DEPLOY_TOKEN` отклоняет любую запись. Так задумано.
